# Simplify setup — interview record and decisions

## User request (2026-10-06, summarized)

The setup process is too hard and over-engineered. Remove Compose hardening options
(`tmpfs`, `cap_drop`, `cap_add`, `security_opt`, `stop_grace_period`, …) and the
base64url setup token. Deploy the app; visiting the domain redirects to setup;
enter username, password and re-enter password. Passwords of 8–16 characters are
fine (MFA will come later). Then a page for language, timezone, site title, etc.
After setup, the domain goes to login. Database setup and schema changes must be
applied automatically at deployment, including future data migration scripts.
Adjust docker compose, the env example and all related docs.

## Design decisions (agent, within the approved scope)

| ID  | Decision                                                                                                                                                                                                                                                                                                        | Rationale                                                                                                          |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| D1  | **New migration baseline.** Replace migrations `0000`–`0004` with a fresh baseline (generated tables + one reviewed custom SQL file for triggers/FTS). Data from pre-release builds is detected and refused with a clear "start fresh" message.                                                                 | Greenfield (answer 5). Removes the obsolete setup-secret table and pre-release restore path.                       |
| D2  | **Backup archive format v2.** Format-v1 archives (pre-release) are rejected with a clear message.                                                                                                                                                                                                               | Old archives have no username/email and an obsolete schema; greenfield.                                            |
| D3  | **Email is required** in setup, trimmed, basic syntax check, ≤254 chars, changeable in Settings. Not verified (no SMTP yet), never shown publicly.                                                                                                                                                              | Answer 2 says "add email field"; requiring it now avoids a later "please add your email" migration.                |
| D4  | Username/email changes in Settings require **fresh authentication** (password, plus TOTP/recovery code when MFA is on).                                                                                                                                                                                         | The username is a login credential; follows existing sensitive-action pattern.                                     |
| D5  | Setup **window = 60 minutes from process start** while no account exists; in memory only; a restart reopens it.                                                                                                                                                                                                 | Answer 1. Zero configuration; cuts exposure of a forgotten fresh deployment.                                       |
| D6  | **Partial translation is allowed and labelled.** zh-CN covers setup, login/MFA, navigation shell and Settings → General/Account in this change; other text falls back to English per string.                                                                                                                    | Answer 7: "full translation is not in place yet". Not claiming a fully translated UI.                              |
| D7  | Private-network peers (loopback, RFC 1918, IPv6 ULA/link-local) are trusted to supply **one** `X-Forwarded-For` address; public peers never are. Exact-proxy-IP configuration and static Compose IPs are removed.                                                                                               | Answer 11. The app publishes no port; Caddy (default config) replaces client-supplied XFF with the real client IP. |
| D8  | **Maintenance commands run inside the image** by name: `reset-password`, `reindex`. They do not re-own the data folder; they drop to PUID/PGID first and refuse if the folder is not owned by it.                                                                                                               | Answer 16; avoids a full ownership walk racing a running server.                                                   |
| D9  | `reset-password` is safe while the app is running (single SQLite IMMEDIATE transaction; server reads auth state from the DB). `reindex` still needs the app stopped.                                                                                                                                            | One command, no stop/start dance, for the common lost-password case. Must be proven by a test (ACCEPTANCE OPS-02). |
| D10 | The container entry **always** uses `/data` regardless of a `DATA_DIR` in `.env`; dev defaults `DATA_DIR=./data`, `ORIGIN=http://localhost:5173` (dev) / `http://localhost:3000` (`npm start`, non-production only).                                                                                            | `.env` stays one line; no conflict between dev and container values.                                               |
| D11 | Compose relies on Docker/Podman **default** capabilities (they include CHOWN, DAC_OVERRIDE, FOWNER, SETUID, SETGID, KILL). No `init: true`: the server is PID 1 after `execve` and adapter-node handles SIGTERM. Image `HEALTHCHECK` stays in the Dockerfile.                                                   | Answer to the request to drop hardening; behavior verified by tests rather than by Compose options.                |
| D12 | Without `stop_grace_period`, Docker allows 10 s for shutdown. A backup interrupted by a stop is marked failed by the existing crash-safe startup cleanup; the user retries. Restore replacement stays journaled.                                                                                                | Accepts the simpler default; no data loss path.                                                                    |
| D13 | Pre-upgrade copy: before applying pending migrations to an existing database, write `data/pre-upgrade/` (SQLite online backup + manifest; migrations never change key material), replacing the previous copy atomically. Insufficient space → do not migrate, do not start, clear log. Not included in backups. | Answer 15. Enables image rollback right after an upgrade.                                                          |
| D14 | Data migration steps are TypeScript functions registered in application code by schema version, run in the **same transaction** as that version's SQL; DB-only, synchronous, deterministic. Filesystem migrations need their own design.                                                                        | Answer 14. Transactional all-or-nothing; filesystem changes cannot join a SQLite transaction.                      |
| D15 | The bundled-Caddy stack is removed from the user-facing deployment. The release drills keep a **test-only** Caddy Compose under `tests/release/`.                                                                                                                                                               | Answer 10; drills still need HTTPS with two domains.                                                               |
| D16 | Remove manual migration, setup-secret issuance and stdin-JSON recovery scripts. Local maintenance: `npm run reset-password`, `npm run search:reindex`.                                                                                                                                                          | Answers 12, 13, 16. One way to do each thing.                                                                      |
